# 开源发布说明

## 可以公开什么

只发布已审查的源码、通用应用图标、合成测试和公开说明。允许清单是 `scripts/open-source-allowlist.json`，每个文件都需要明确列出；新增文件不会自动进入发布包。

不要直接压缩整个正在使用的项目，也不要将现有仓库直接改为公开。`.gitignore` 只能阻止未跟踪文件被正常添加，不能删除历史提交、作者邮箱、已跟踪私人文档或远端已经存在的内容。

## 生成发布副本

```powershell
python scripts/export-open-source.py
```

工具在写入前核对所有文件，拒绝符号链接和目录跳转，扫描凭证、个人路径、邮箱及图像文本元数据。扫描失败时不生成发布 ZIP；输出不会打印敏感原值。成功输出源码快照、ZIP 和 SHA256 清单，全部放在被 Git 忽略的 `.release/` 下。

导出不携带 `.git/`，也不会上传、创建远端仓库或启动工作台。正式发布只使用这一份经过复核的副本。

## 明确排除的内容

- 本机应用数据目录、浏览器配置文件、Cookies、`localStorage` 导出、聊天记录、Obsidian 笔记和 PDF。
- `.cache/`、数据库、日志、截图、备份、社交附件和账号认证文件。
- 图片生成过程的 JSON 和原始图片，里面可能含本机路径。
- 当前协作规则 `AGENTS.md` 和包含本机真实使用案例的旧教程文档。
- 所有旧 Git 对象、提交作者、提交信息、远端配置和历史分支。

## 最后复核

1. 运行回归检查，并查看导出包内文件清单。
2. 人工检查新增文字、注释、测试和图标是否带入个人内容。关键词扫描不能识别所有自然语言隐私。
3. 用独立测试账户或临时环境制作公开截图。原来的工作台会读取实际机器上的数据，不能把正式页面截图当演示图。
4. 项目已采用 MIT，`LICENSE` 必须进入允许清单。确认新增第三方文字、图标和示例的发布范围；运行时用户导入的数据不随源码发布。
5. 在导出目录建立新的 Git 历史，先检查将公开的作者名和邮箱，再推送到确定的目标仓库。不要复制旧 `.git/`。

后续修改再次运行导出和复核。任何变化后的文件都不继承上一次的审查结果。若旧内容已经公开，新的干净发布包不能撤回他人已获取的副本；需要单独核查远端、历史和已发布附件。

## 运行时边界

静态服务只提供网页实际使用的资源，不提供目录列表、源码后端、缓存和 Git 文件；HTTP 请求需要匹配本机 Host 与 Origin。API 仍按产品功能读取当前使用者自己的本机数据，本机服务不是多用户身份认证系统，不能对外发布服务端口。
